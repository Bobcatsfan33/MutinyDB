# Security policy

## Supported versions

The latest tagged v0.1 developer release receives security fixes. It is supported for evaluation,
not approved for production until the external-KMS custody and external-assurance gates clear.

## Reporting a vulnerability

Do not open a public issue. Use GitHub's private vulnerability reporting on the repository's
Security tab. Include affected versions, reproduction steps, impact, and any suggested mitigation.
The maintainers will acknowledge a complete report within three business days, coordinate a fix
and disclosure, and credit reporters who want attribution.

Never include real credentials, customer data, KMS material, or exploit traffic against systems
you do not own. The quickstart operator token is intentionally a demo credential and must not be
used in a deployment.
